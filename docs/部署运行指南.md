# 内嵌 AI 意图 SDK · 部署与运行指南

> 本文档说明如何在 ruoyi-office 宿主系统中运行「内嵌 AI 意图 SDK」MVP。

## 一、架构角色划分

| 仓库/模块 | 角色 | 说明 |
|-----------|------|------|
| `next-agent`（本仓库） | **SDK 产品** | `intent-protocol`（协议 DTO）、`intent-sdk-core`（执行引擎内核，无 Spring / 无 pi 依赖）、`intent-sdk-host`（宿主 SPI + 声明式事实规则引擎）、`intent-sdk-pi`（pi-java 执行器实现，唯一依赖 pi 的模块）、`intent-spring-boot-starter`（自动装配）、`intent-sdk-gateway`（可组装网关客户端） |
| `ruoyi-office/yudao-module-intent` | **宿主平台装配** | 意图 REST API、UI 静态资源、SDK Bean 装配。与业务完全解耦 |
| `ruoyi-office/yudao-module-crm` | **业务侧接入** | 声明宿主工具（`CrmIntentConfiguration`）+ 意图规范（`resources/intent/*.yaml`） |

业务系统接入工作量 = **声明工具 Bean + 放意图 YAML**，平台模块零改动。

## 三、构建与启动（后端）

> ⚠️ **必须使用 `-P boot` 构建**：ruoyi-office 是 cloud/boot 双模式工程。默认的 cloud 模式会把每个模块打成 Spring Boot fat jar，单体模式下 Spring 无法扫描嵌套 jar 中的类（表现为 `PermissionCommonApi` 等 bean 大量缺失、启动失败）。`-P boot` 会让模块保持普通 jar，由 yudao-server 统一打包。

```bash
# 1. 构建 SDK 并安装到本地 Maven 仓库
cd next-agent && mvn install -DskipTests

# 2. 构建宿主（单体模式：-P boot；含 crm / intent 模块）
cd ruoyi-office/ruoyi-office && mvn -pl yudao-server -am clean install -DskipTests -P boot

# 3. 启动（单体模式，Nacos 已禁用）
java -jar yudao-server/target/yudao-server.jar
```

> ⚠️ **Windows：启动 JVM 前把 TEMP/TMP 指到普通目录**（`tools/run-backend.cmd` 已封装）。
> 本机 `C:\Users\<user>\AppData\Local\Temp` 下 AF_UNIX socket 创建会**静默失败**（bind 不报错但不落文件），
> 导致 JDK 无法建立 Selector 的内部唤醒管道，任何用到 NIO Selector 的组件都会崩：
> Redisson / Netty 报 `failed to create a child event loop`，或 esbuild 报 `VirtualAlloc failed errno=1455 / out of memory`。
>
> ```bat
> set "TEMP=D:\javatmp"
> set "TMP=D:\javatmp"
> java -Xmx1280m -jar yudao-server\target\yudao-server.jar
> ```
>
> 判断方法：`java -Djava.io.tmpdir=<普通目录> -e` 之类的探针意义不大，直接跑一句
> `SelectorProvider.provider().openSelector()` 即可复现/验证。

## 五、关键 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin-api/intent/catalog` | 意图目录（含网关状态） |
| POST | `/admin-api/intent/execute` | 执行意图 `{intentId, params, context}` |
| GET | `/admin-api/intent/history?limit=20` | 当前用户执行历史 |
| GET | `/admin-api/intent/trace/{traceId}` | 执行留痕（步骤级） |
| POST | `/admin-api/intent/feedback` | 结果评价 |
| GET | `/admin-api/intent/status` | 平台状态 |

目录增强（动态提示与建议）随目录接口返回，不新增接口：

```yaml
intent:
  suggestions:               # 目录增强：宿主事实驱动的提示与建议（不经过 LLM）
    enabled: true            # 关掉即退化为纯静态目录
    max: 5                   # 每条业务规则最多返回几条建议（各规则配额独立）
    cacheSeconds: 30         # 宿主侧缓存秒数；意图执行成功后该用户缓存立即失效
```

- `GET /admin-api/intent/catalog?page=crm/contract` 额外返回 `entries[].badge`（如 `{"text":"2 份合同即将到期","level":"warning","count":2}`）与 `suggestions[]`（含 `intentId` / `params` / `reason`，前端点击即用这些参数执行）；
- 业务系统按需实现 `IntentCatalogEnricher`（宿主 Bean，参考 `CrmIntentCatalogEnricher`），平台与前端无需改动。

## 六、常见问题

- **登录报验证码错误**：在 `application-local.yaml` 增加 `yudao: captcha: enable: false`。
- **LLM 401**：检查 `DEEPSEEK_API_KEY` 环境变量或 `intent.llm.api-key` 配置。
- **换 LLM 供应商**：改 `intent.llm.*`（支持 deepseek/openai/anthropic/custom OpenAI 兼容端点），不改代码。
- **新增意图**：业务模块放一个 YAML 到 `resources/intent/` + 声明工具 Bean，重启即生效。
- **页面没有提示徽标/建议**：① 徽标只挂当前页面已装载的意图（例如合同意图只在 `crm/contract` 显示）；② 确认 `intent.suggestions.enabled=true`；③ 启动日志看是否加载到规则：`[intent] 声明式事实规则: N 条，事实源 M 个`（N=0 说明 `intent-rules/*.yaml` 没被扫到）；④ 规则的 `scope.page` 前缀与当前路由是否匹配；⑤ 事实查询失败会被静默降级，查宿主日志 `[intent]` 前缀；⑥ `cacheSeconds` 内不刷新，可等 30s 或执行一次意图强制刷新。
